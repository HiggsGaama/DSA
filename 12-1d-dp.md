## 1. Active Recall Pre-Test (15 Minutes)
Attempt to answer these questions on paper before expanding the solutions.

<details>
<summary><strong>Prompt 1: What two essential mathematical properties must a problem satisfy to be solvable via Dynamic Programming?</strong></summary>

1. **Optimal Substructure**: An optimal solution to the global problem contains within it optimal solutions to its constituent subproblems.
2. **Overlapping Subproblems**: The recursive space repeats the exact same subproblem evaluations multiple times (unlike Divide & Conquer like Merge Sort, where subproblems are completely independent and disjoint). Memoizing or tabulating these states avoids exponential redundant computation.
</details>

<details>
<summary><strong>Prompt 2: In Maximum Product Subarray, why is maintaining a single `dp[i]` tracking the maximum product up to $i$ insufficient?</strong></summary>

Multiplication involves negative numbers. 
Multiplying a large negative number by another negative number yields a large positive product! 
Therefore, the minimum (most negative) product ending at index $i - 1$, when multiplied by a negative `nums[i]`, can suddenly become the new maximum product at index $i$. 
We must concurrently track both `max_prod[i]` and `min_prod[i]`.
</details>

<details>
<summary><strong>Prompt 3: How does the Patience Sorting / Binary Search algorithm improve Longest Increasing Subsequence (LIS) from $O(N^2)$ to $O(N \log N)$?</strong></summary>

Maintain an array `tails` where `tails[len]` stores the *smallest tail element* of all increasing subsequences of length `len + 1` found so far.
For each element $x$ in the array:
- If $x$ is greater than all elements in `tails`, append $x$ (increasing the longest length by 1).
- Otherwise, find the smallest element in `tails` that is $\ge x$ using binary search (`bisect_left`) and replace it with $x$.
Because `tails` is strictly sorted, each element is processed in $O(\log N)$ time, yielding $O(N \log N)$ total time.
</details>

### Core Invariants & Mental Model
1. **State Definition Rigor**: Always write down in words what $dp[i]$ represents before writing code.
   - *Example*: "$dp[i]$ = the minimum number of coins needed to make change for amount $i$."
2. **The Recurrence Relation**: Express $dp[i]$ as a function of previous states:
   $$dp[i] = 1 + \min_{c \in \text{coins}, c \le i} dp[i - c]$$
3. **Space Optimization (Rolling Variables)**: If $dp[i]$ only depends on $dp[i - 1]$ and $dp[i - 2]$ (as in Fibonacci, Climbing Stairs, and House Robber), drop the $O(N)$ array and maintain two scalar variables (`prev1`, `prev2`) for $O(1)$ space.

## 3. Canonical Code Templates

### Pattern A: State Transition with Space Optimization (House Robber — $O(N)$ Time, $O(1)$ Space)
```python
from typing import List

def rob(nums: List[int]) -> int:
    rob_prev = 0 # Max profit robbing up to house i-1
    rob_curr = 0 # Max profit robbing up to house i
    
    for num in nums:
        # State decision: Rob current house + profit from i-2, OR skip current house
        new_rob = max(rob_curr, rob_prev + num)
        rob_prev = rob_curr
        rob_curr = new_rob
        
    return rob_curr
```

### Pattern B: Unbounded Knapsack Transition (Coin Change — $O(A \times C)$ Time)
```python
from typing import List

def coin_change(coins: List[int], amount: int) -> int:
    # dp[i] represents min coins to make amount i
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0 # Base case: 0 amount requires 0 coins
    
    for a in range(1, amount + 1):
        for c in coins:
            if a - c >= 0:
                dp[a] = min(dp[a], 1 + dp[a - c])
                
    return dp[amount] if dp[amount] != float('inf') else -1
```

### Pattern C: Patience Sorting LIS ($O(N \log N)$ Time, $O(N)$ Space)
```python
import bisect
from typing import List

def length_of_lis(nums: List[int]) -> int:
    tails = []
    
    for x in nums:
        idx = bisect.bisect_left(tails, x)
        if idx == len(tails):
            tails.append(x)
        else:
            tails[idx] = x # Lower the tail bound for subsequence of length idx + 1
            
    return len(tails)
```

## 4. Coding Deep Dive: Worked Walkthrough (50 Minutes)

### Problem: Coin Change (LeetCode 322)
**Problem Statement**: You are given an integer array `coins` and an integer `amount`. Return the fewest number of coins needed to make up that amount, or `-1` if that amount cannot be made.

#### Pen-and-Paper Dry Run Trace
Let `coins = [1, 2, 5]`, `amount = 7`.
Initialize: `dp = [0, inf, inf, inf, inf, inf, inf, inf]`.

| Amount `a` | Coin $c=1$ (`1 + dp[a-1]`) | Coin $c=2$ (`1 + dp[a-2]`) | Coin $c=5$ (`1 + dp[a-5]`) | `dp[a]` Final Value |
|:---:|:---:|:---:|:---:|:---:|
| 0 | - | - | - | **0** |
| 1 | $1 + dp[0] = 1$ | - | - | **1** (coin: 1) |
| 2 | $1 + dp[1] = 2$ | $1 + dp[0] = 1$ | - | **1** (coin: 2) |
| 3 | $1 + dp[2] = 2$ | $1 + dp[1] = 2$ | - | **2** (coins: 1+2) |
| 4 | $1 + dp[3] = 3$ | $1 + dp[2] = 2$ | - | **2** (coins: 2+2) |
| 5 | $1 + dp[4] = 3$ | $1 + dp[3] = 3$ | $1 + dp[0] = 1$ | **1** (coin: 5) |
| 6 | $1 + dp[5] = 2$ | $1 + dp[4] = 3$ | $1 + dp[1] = 2$ | **2** (coins: 5+1) |
| 7 | $1 + dp[6] = 3$ | $1 + dp[5] = 2$ | $1 + dp[2] = 2$ | **2** (coins: 5+2) |

Result: `dp[7] = 2` (using coins `5 + 2`).
Time Complexity: $O(\text{amount} \times |\text{coins}|) = O(7 \times 3) = O(21)$.
Space Complexity: $O(\text{amount})$ array.

## 6. Post-Session Active Recall Flashcards (15 Minutes)

<details>
<summary><strong>Flashcard 1: In Coin Change II (combinations) vs Coin Combinations I (permutations), what single code change determines whether order matters?</strong></summary>

The **loop nesting order**:
- **Combinations (Order does NOT matter, $[1, 2] \equiv [2, 1]$)**: Loop over **coins** in the outer loop, and **amounts** in the inner loop. Each coin is considered sequentially, preventing permuted repeats.
- **Permutations (Order DOES matter, $[1, 2] \ne [2, 1]$)**: Loop over **amounts** in the outer loop, and **coins** in the inner loop. At any target amount, every coin is eligible as the final step.
</details>

<details>
<summary><strong>Flashcard 2: In House Robber II (circular houses where the first and last house are adjacent), how is the circular constraint cleanly resolved?</strong></summary>

Run standard House Robber twice on two linear slices:
1. Candidate 1: `rob(nums[0 : N - 1])` (includes house 0, excludes house $N-1$).
2. Candidate 2: `rob(nums[1 : N])` (excludes house 0, includes house $N-1$).
Return $\max(\text{Candidate 1}, \text{Candidate 2})$.
</details>

<details>
<summary><strong>Flashcard 3: Why does `tails` in the $O(N \log N)$ LIS algorithm NOT necessarily represent the actual elements of the longest subsequence?</strong></summary>

`tails` only maintains the optimal *smallest possible tail values* for subsequences of each length. 
When an incoming value overwrites an interior slot of `tails`, it allows subsequent elements to build upon a smaller threshold, but it corrupts the historical sequence order of elements already in `tails`. 
The *length* of `tails` is strictly guaranteed to be the maximum LIS length, but reconstructing the actual sequence requires tracking predecessor index pointers.
</details>
